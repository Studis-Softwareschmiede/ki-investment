# Reviewer-Selbst-Lessons (ki-investment)

- 2026-07-12 (S-027, Iter.1) — **Secret-Sync-Gate Zeile 3 (`.env.gpg` unverändert nach neuer `.env.example`-Variable) ist in diesem Projekt für explizit als "Kein Secret-Wert" markierte Konfig-Skalare mit Code-Default ein etabliertes, akzeptiertes Muster — kein Blocker.** `TOLERANZ_CONFIG` (S-013) wurde genauso eingeführt (auskommentiert, "Kein Secret-Wert", Default in `app.config`) und `.env.gpg` wurde dabei nicht angefasst; die Story ist gemergt. `HALLUZINATIONS_KPI_SCHWELLWERT` (S-027) folgt demselben Muster. Bei neuen `.env.example`-Einträgen zuerst `git log -p -- .env.example` auf ein Präzedenzmuster prüfen, bevor die Heuristik als Important gemeldet wird — sonst falsch-positiver Blocker gegen etablierte Projekt-Konvention (nur echte Secrets landen in `.env.gpg`, Konfig-Skalare mit sicherem Default nicht).
- 2026-07-12 (S-016, Iter.1) — **Vor dem Melden von "`.env.gpg` nicht re-encrypted" (Secret-Sync-Gate Signal 3) immer erst `git log -p -- .env.example` auf Präzedenzfälle prüfen — bestätigt hier erneut für `EINSTAND_METHODE_DEFAULT` (S-016, gleiches Muster wie TOLERANZ_CONFIG/HALLUZINATIONS_KPI_SCHWELLWERT): Konfig-Skalar mit sicherem Code-Default + "Kein Secret-Wert"-Kommentar ist etabliertes Projekt-Muster, kein Blocker.**
