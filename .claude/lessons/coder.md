# Coder-Lessons (ki-investment)

- 2026-07-12 (S-003, Iter.1, dba) — **`server_default` in Migration UND ORM-Modell synchron deklarieren.** Setzt eine alembic-Migration `server_default=...` auf einer Spalte (z.B. `sa.Column(..., server_default=sa.false())`), muss `mapped_column(...)` im SQLAlchemy-Modell denselben `server_default` tragen — nicht nur `default=...` (das ist rein Python-/ORM-seitig, für Alembic-Autogenerate/`alembic check` unsichtbar, alembic/A07+A09). Sonst entsteht eine Modell/DB-Drift, die `alembic check` mangels `compare_server_default=True` (nicht Default) nicht erkennt.
- 2026-07-12 (S-003, Iter.1, dba) — **Seed-Inserts ON-CONFLICT-fest bauen, wenn `docs/data-model.md` Idempotenz fordert.** `op.bulk_insert()` erzeugt eine reine INSERT-Anweisung ohne Konfliktbehandlung. Verlangt das Modell für eine Seed-Migration explizit „idempotent seedbar (ON CONFLICT DO NOTHING)", stattdessen `op.execute(sa.text("INSERT ... ON CONFLICT (...) DO NOTHING"))` verwenden — oder, falls bewusst darauf verzichtet wird (z.B. weil `alembic_version` Doppel-Apply ohnehin verhindert), die Abweichung im Migrations-Docstring explizit begründen statt sie stillschweigend zu übergehen.
- 2026-07-12 (S-003, Iter.1) — **Diff im zugewiesenen Worktree erzeugen, nicht im Haupt-Repo-Ordner.** Der Coder-Diff für S-003 (app/db/*, alembic.ini, tests/db/*, pyproject.toml/uv.lock) lag unkommittiert im geteilten Haupt-Checkout (`/Users/alex/Git/Studis-Softwareschmiede/ki-investment`) statt im für die Session vorgesehenen `.claude/worktrees/<session>`-Ordner. Risiko: `git reset`/`checkout`/`clean` einer anderen parallel laufenden Session im selben Hauptordner kann diese Änderungen kommentarlos löschen (siehe CLAUDE.md „Parallelbetrieb: mehrere Cloud-Sessions", dokumentiertes Vorfallmuster). Vor dem ersten Schreib-Zugriff auf Code/Board immer zuerst in den eigenen Worktree wechseln bzw. `EnterWorktree` aufrufen, dort committen+pushen.
